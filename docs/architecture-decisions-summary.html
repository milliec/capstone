The detail

01Pattern, and whyDecided A workflow. The order of work is written in code and never changes.

Why a workflow

  • The path is known in advance, and the three gates must sit at fixed points.
  • It is easy to observe (“stage A finished”), and its cost and time are bounded.

Rejected

  • Planning agent: it could skip or reorder work around a gate.
  • One big model call: no separate checker, and no gate between extraction and judgement.
  • Self-correcting loop: the specialist, not a model, settles each flag.
  • Routing: every run takes the same path.

Reference shape: a document pipeline, with a named route for every way a model can be wrong. No agent has a tool.

Sources: SAD Pattern Decision, Reference Architecture.

02Crews, Flows or hybridDecided Neither a Flow nor a multi-agent crew: three single-agent crews, called by plain backend functions.
  • Started as a hybrid: a CrewAI Flow wrapping each stage (DL-17).
  • Changed because with five focused days, the Flow added framework to learn and debug without changing who owns the gates (DL-35).
  • “Multi-agent” here means three agents with separate roles, models and prompts. None plans its own steps.
  • CrewAI is still used for the agents, tasks, structured outputs, guardrails and limits. The library is free; the cost is the model calls.

Sources: SAD §2, DL-17, DL-35.

03Agent designDecided Each agent has a written card in SAD §2; the configuration files are built from it.
AgentRoleGoal, in one lineReturns
ExtractorRegulatory text extractorTurn one source document into fixed-schema rows, quoting the deadline word for wordRows
VerifierIndependent checkerReport where a row disagrees with its own quote or another source, with evidenceFlags
JudgeApplicability reviewerDecide applies / does not apply / unsure, citing fund facts, in plain EnglishOne verdict

Rules for all three

  • The answers never reach a prompt. The loader strips the mock files’ test notes and “Decides” column; test T-LEAK-1 fails if any get through.
  • Examples are checked too. Test T-EXAMPLE-1 fails if an example’s quote matches any mock source paragraph.
  • A failed check ends the run. The model is never asked to try again.
  • The judge’s key rule: a fact counts only when what it asserts meets the condition as the rule words it; otherwise “unsure”.

Sources: SAD §2 “Agent cards”, DL-39, DL-41.

04Roster, tasks and handoffsDecided Three agents, about 17 model calls a run. Everything else is code.
  • Who files is never guessed. At G1 it is chosen from the filing parties only (AIFM, Fund administrator, Auditor, Local reporting agent (Spain), Tax advisor) or “not known”.
  • For grading, code maps the extractor’s wording to a party name with a fixed lookup, frozen before the first evaluation run (EC-R11, DL-41).
  • Code steps: loading, the quote check, the coverage view, dates, gates and the audit log.

Sources: SAD Work Ownership, Delegation Map, DL-39, DL-41.

06Deployment shapeDecided Local, one process. A public hosted demo is an optional stretch goal.
  • Pages are plain server-rendered HTML with one stylesheet; no JavaScript framework (Next.js is post-course).
  • Evaluation runs happen locally. CI never holds a model key.
  • Before hosting, you confirm Railway’s pricing and set a spend limit. If the visual pass is dropped, the link is not shared publicly until it is done.

Sources: SAD §5, §8, “Stretch goal: hosted portfolio demo”, DL-33, DL-38.
